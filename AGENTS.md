# AGENTS.md｜Ideas Repository Agent Rules — Successor Candidate

## Repository Role

This repository is a **Carrier / Projection surface for the Ideas Stable Native responsibility**.
It is not a Canon Root, Global Router, Authority aggregator, or permanent runtime home.

Ideas responsibility is bounded to:
- Meaning
- Identity
- Placement
- Reader eligibility
- Navigation
- Lineage
- Successor / historical metabolism

Repository location, branch name, latest modification time, or agent/provider identity does not establish Native Current or Authority.

## Need-First Entry

Before acting, resolve the smallest sufficient chain:

`Need → StableReferent → Affected Ideas Slice → Required Capability → Source/Evidence → Authority/Rights → Receiver → Exit/Re-entry`

Do not route work by historical window, provider, model, or agent name.

## Allowed Work

Within the authorized affected slice, agents may:
- inspect repository evidence and diffs;
- identify Meaning / Identity / Placement / Reader / Navigation / Lineage deltas;
- detect duplicate, historical resurrection, naming drift, reader ambiguity, and successor gaps;
- propose or apply bounded reversible repository edits when authorized;
- preserve provenance and predecessor/successor relation;
- prepare receiver-specific Return evidence;
- run bounded readback/regression checks.

## Protected Boundaries

Agents must not infer or claim:
- `Latest == Current`;
- `Repository == Native Authority`;
- `Readable == Authorized`;
- `Carrier / Provider / Agent == Identity or permanent role`;
- `Representation == Identity`;
- `Historical == Current`;
- `Return Written == Receiver Rebuilt`.

Dependency, State, Constraint, Gate, Authority, Binding, Transition, and Return/Rebuild judgment belong to DCP when materially affected.
World, Object, Relation, Reality, Geometry, Render/Parametric admission, and Reconstruction belong to GLModel when materially affected.

## Provider / Agent Rule

ChatGPT, Codex, Jules, Gemini, Claude, Astra, Skills, Work surfaces, or future providers are **capabilities/carriers**, not permanent governance roles.
Select them only when the current Need requires their capability and the action is authorized.

No fixed `reviewer → coder → documenter` chain is required.

## Change / Review Gate

Before writing, check:
1. exact StableReferent and affected Ideas slice;
2. source/base revision;
3. whether the change overlaps another material effect;
4. authorization and disclosure boundary;
5. receiver and readback requirement;
6. rollback / successor / exit condition.

If Native Current is unknown or conflicting, preserve `UNKNOWN / TO_VERIFY / CONFLICT / HOLD`; do not synthesize Current from repository state.

## Output / Return

Prefer concise, receiver-readable evidence rather than fixed PASS/HOLD forms.
A material Return should preserve at least:
- StableReferent
- Need / affected slice
- Source + revision
- Evidence class
- change/disposition candidate
- Authority ceiling
- Receiver
- Rebuild/retest or re-entry condition

## Final Rule

No automatic merge, publication, deployment, destructive action, or Native promotion.
A repository edit can be a valid carrier mutation without becoming Native adoption.
